## 🧠 Context to carry forward
The shape that made this go through in one pass, if anyone revisits it:

- `pairRel a b c d : (3(a+b)+1)·c·d = a·b·(3(c+d)+1)` is symmetric in `a↔b`,
  `c↔d`, **and** pair↔pair. Each symmetry is a one-line `linear_combination`
  (pair↔pair is `linear_combination -h`). Those three lemmas are what let a
  single "small label in the first slot" core lemma cover all four positions —
  no case duplication anywhere downstream.
- The decisive move is rewriting `pairRel` as the **bilinear**
  `key : 3(a-c)·b·d + a(3c+1)·b = c(3a+1)·d`. Then each sign of `a-c` lets you
  drop one strictly-positive term and cancel one strictly-positive variable, so
  the *other* variable gets a numeric bound: `c < a ⇒ b < 8`, `a < c ⇒ d < 19`
  (for `a ≤ 5`). That is what converts an unbounded Diophantine problem into
  `interval_cases`. Without it you have no handle, since **no upper bound on the
  partner `b` is assumed** — the theorem is genuinely over all positive odd
  labels, not a finite scan.
- Bounding the *smaller* new label is the separate `r_u = 2u/(3u+1) < 2/3`
  estimate. `MinimalRepairs.smaller_factor_bound` is `private`, so I copied the
  short `nlinarith` argument locally as `pair_smaller_bound` (as the kickoff
  permitted) and instantiated it at `D = 3(a+b)+1, A = ab, M = 2a+1`; both side
  conditions are pure positivity.
- Oddness of `b` is load-bearing exactly once: it kills the residual
  `a=5, c ∈ {7,9}` solutions, which give `b = 18, 28, 84, 198` — integral but
  even. Dropping `hbo` would make the statement false-looking there.
- Multiplicity needed **no** injectivity side-condition, contra the kickoff's
  hedge: either the small label is in neither pair (both counts 0) or the pairs
  are equal as multisets, so `count` agrees even when both labels coincide.
- Why this obstruction is stronger *in kind* than the earlier cubic
  `{7,65,133} → {13,19,29}` one: that was a finite-component argument and dies
  once `r121` is adjoined. A conserved count survives adjoining anything.

## ⚠️ Gotchas
- `interval_cases d` will not accept a *symbolic* bound like
  `3*(c-a)*d < a*(3*c+1)`. Sequence it as
  `interval_cases c <;> (have hdb : d < 19 := by omega) <;> interval_cases d <;> omega` —
  once `c` is a numeral the bound is linear and `omega` produces it, and in the
  even-`c` branches `omega` closes from `hco : c % 2 = 1` outright.
- `rcases hmem with ... | rfl` substitutes the *label* away (`d` becomes `x`), so
  a later `Multiset.pair_comm d c` fails with "unknown identifier `d`". Use
  `Multiset.pair_comm _ _` with `rw [← h]`.
