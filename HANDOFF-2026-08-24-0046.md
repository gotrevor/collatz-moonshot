  exponent-2/3 file `BackwardTwoThirds.lean`. When you build the *next* rung's

- **Scale-up map from 2/3 → 3/4** (memorize this, it's the whole trick):
  source residue mod 243→**729**, child/potential residue mod 81→**243**, shared
  digit `t = x/81%3` → `x/243%3`, edge weight `(52/25)(629/1000)^j` →
  `(2279/1000)(2973/5000)^j`, integer scale `25·1000^23` → `1000·5000^23`,
  underweight facts `(52/25)^3<9,4(629/1000)^3<1` →
  `(2279/1000)^4<27, 8(2973/5000)^4<1`. Height floors changed from
  `{1,7/4,5/2,3,4}` to `{1,7/4,3,6,12}` and the transition maps are DIFFERENT
  (see below).
- **Height transitions are the one genuinely new bit**, because the pinned
  `nextThreeQuartersState i j = min(i+(j-2),4)` and `shrinkThreeQuartersState
  i = i-1` differ from the 2/3 ad-hoc `if` tables. I proved growing by splitting
  `j<6` (interval_cases, everything concrete, `fin_cases i <;> simp_all <;>
  omega`) vs `j≥6` (state is always top `⟨4⟩`; feed omega `64 ≤ 2^j` and
  `64*x ≤ 3y+1`). Verified all floor ratios by hand first (each j-step ~×2,
  cap makes large-j trivially safe) — they hold.
- **native_decide was explicitly allowed** for the finite certificate (operator
  instruction). The certificate array is an `Array ℕ` (810 entries) with scale
  `5000^23 ≈ 10^85`; kernel `decide` would die, native is instant. Expected and
  fine that `#print axioms` shows the native_decide axiom.
- The frozen 810-entry `threeQuartersWeights` table + all pinned defs +
  the `exists_threeQuartersExpansion` statement were **preserved verbatim** —
  do not touch them. Only added helper defs/lemmas and replaced the `sorry`.
