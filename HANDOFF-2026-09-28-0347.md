## 🧠 Context to carry forward

- **The crux was not any article statement — it was a missing prerequisite.**  §16.3, §16.5 and
  §16.7.2 are all *distance along a vertical loop* claims, and `tA` is multiplication by `2⁻¹`
  mod the column coefficient.  So all three reduce to the multiplicative order of `2` mod `3ⁿ`,
  which mathlib does not have.  New file `MSP2/Order.lean` supplies it from one
  lifting-the-exponent induction that **carries the cofactor's residue**:
  `2^(3ⁿ) = -1 + 3^(n+1)·c` with `c ≡ 1 (mod 3)`.  The `-1` plus the exact valuation of
  `2^(2·3ⁿ)-1` gives `orderOf (2 : ZMod (3^(m+1))) = 2·3^m`; the *extra* `c ≡ 1 (mod 3)` —
  unnecessary for the order — pins the cube root of unity `2^(2·3ⁿ) ≡ 1 + 3^(n+1) (mod 3^(n+2))`,
  which is exactly what §16.5 needs.  Strengthening the induction beyond what the immediate goal
  demanded is what made the third theorem cheap.
- **The reusable workhorse is `tA_iterate_eq`**: for odd `A` and `b, x < A`,
  `2^i · x ≡ b [MOD A] → (tA A)^[i] b = x`.  A vertical distance is *pinned by a congruence plus a
  bound*.  Every §16 distance theorem is then one `linear_combination` over ℤ (via
  `Nat.modEq_iff_dvd`) and two `omega` bounds.  If the Generator Table gets formalized, this is the
  interface to reuse — don't re-derive iterate arithmetic.
- **`covered_iff_msp2` needed no minimality argument.**  I planned a "first dip is a halving"
  argument and it turned out unnecessary: the skipped Collatz value is `3v+1 > v`, so if `3v+1 < N`
  then `v < N` already, and `v` is an MSP² iterate.  The proof is just the two-case invariant
  "every Collatz iterate is an MSP² iterate or a skipped image of one".
- **§16.5's alternation is real, and its source is `cLeft`, not the vertical rule.**  With
  `ω := 2^(2·3ⁿ)` fixed, `ω·Bₙ ≡ Cₙ` for odd `n` but `ω·Cₙ ≡ Bₙ` for even `n` (checked:
  `10·13 ≡ 22 mod 27`, `28·13 ≡ 40 mod 81`).  The asymmetry is that `cLeft` has a parity-dependent
  closed form (`2Cₖ+1 = 3^(k+1)` for `k` even, `5·3^(k+1)` for `k` odd) while `2Bₖ+1 = 3^(k+2)`
  does not.  I wrote a stronger (wrong) version of this note first and corrected it in `dfe1d8f`-ish
  — if a successor reasons about §16.5, trust the Lean statement, not a "the congruence doesn't
  alternate" intuition.
- **Frozen-statement discipline held.** Two statements (`msp2_odd_run`'s `hr : 1 ≤ r`,
  `covered_iff_msp2`'s `hN : 2 ≤ N`) turned out unnecessary — proved without them, which is a
  strengthening.  I deliberately kept the unused binders (and the linter warnings) rather than
  rename or drop them, because the statements are frozen and binder names are API.
