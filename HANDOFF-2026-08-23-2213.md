## 🧠 Context to carry forward
- The mathematical point: all inverse children of one source `x` share the single
  next ternary digit `t = x/81 % 3`; the child formula
  `y ≡ (2^j(x mod 243) − 1)/3 (mod 81)` retains the fixed carry digit. Tracking
  this correlation removes the adversarial three-lift minimum entirely — in the
  acceptance theorem each table entry EQUALS the actual child's potential.
- Architecture choice that worked: instead of the 36-state file's per-inequality
  `norm_num` grind (which would have been ~20–50× heavier at 810 inequalities),
  the certificate is one kernel `decide +kernel` on an integer-scaled form
  (scale `25·1000^23`, exponents ≤ 23 so under the kernel exponentiation
  threshold 256), plus a generic rational bridge (`qpow_scale`,
  `twoThirdsNatImage_eq`). Whole module compiles in ~11 s.
- Before writing Lean, I re-derived the full 810-inequality table in Python from
  the intended Lean formulation (`scratchpad mirror_check.py`, transitions +
  childLift + table indexing) and matched the frozen checker's exact minimum
  ratio `1.016618220460` — this pre-verification is why the Lean compiled nearly
  first-try. Reuse this pattern for any future frozen-table formalization.
- Five-state transitions are proved per-case by `omega` after converting the
  power bound to a *linear* fact (`p·x ≤ 3y+1`); omega cannot handle `2^j·x`
  products directly. Growing cases split `j=2`, `j=3`, `j≥4`; the `j≥4` branch
  needs explicit `simp only [if_neg h2, if_neg h3]` (simp_all won't discharge
  the `if j ≤ 2` conditions there).
- The five-state machine needs `d ≥ 2` in transition lemmas (from the uniform
  bound `y/d ≥ (2^j h − 1/2)/3`); the old two-state one did not.
